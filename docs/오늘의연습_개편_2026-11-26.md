## 1. 클릭이 안 되던 원인 (실측 재현)

### 원인 — `.hero:after` 장식이 히어로 버튼 위를 덮고 있었음

홈 히어로 카드(`.hero`)에는 배경 장식으로 `content:'♪'` 의사요소가 `position:absolute` 로 깔려 있습니다(투명도 0.035).
버튼(`.btn.accent`, `data-act="start-practice"`)은 `position:static` 이라, 위치가 지정된 이 의사요소가 **위에 그려지고 그대로 포인터 이벤트를 가로챕니다.**

390×844(갤럭시 크기)에서 버튼 중앙의 최상위 요소를 확인한 결과:

```
elementFromPoint(버튼 중앙) → SECTION.hero     ← 버튼이 아니라 히어로 섹션
Playwright 클릭 → "<section class="hero">…</section> intercepts pointer events" (타임아웃)
```

데스크톱(1440px)에서는 히어로 레이아웃이 달라 장식이 버튼을 덮지 않아 정상 동작했습니다.
**모바일에서만** `오늘의 연습 시작 ↗` 이 죽어 있었고, 증상이 정확히 "눌렀는데 아무 일도 안 일어난다"였습니다.

### 원인 2 — 모바일 상단 메뉴에서 `오늘의 연습` 이 화면 밖

모바일(≤1040px)에서 상단 메뉴는 가로 스크롤 한 줄입니다. 항목이 9개라 390px 화면에서는
`오늘의 연습` 이 x=431~513 으로 **화면 오른쪽 밖**에 있었습니다. 스크롤해야 닿기 때문에 "눌러도 안 되는" 것처럼 보입니다.

### 수정

- `src/styles.css` — `.hero:after{… pointer-events:none}` (장식이 클릭을 받지 않음)
- `src/styles.css` — 모바일에서 `.nav button[data-nav="practice"]{order:-1}` 로 **`오늘의 연습`을 메뉴 맨 앞**에 고정(연한 강조 배경, 활성 시 진한 배경)
- `tools/verify_data.py` — `.hero:after` 에 `pointer-events:none` 이 없으면 실패하도록 회귀 검사 추가
- `tools/e2e_check.py` — 홈 히어로 버튼의 최상위 요소가 `BUTTON` 인지, 좌표 탭(모바일은 `touchscreen.tap`)으로 실제 탭해 `오늘의 연습` 화면이 열리는지 검사

## 2. 오늘의 연습 화면 개편

### 맨 위 — 오늘 할 일 3가지 (한눈에 보기)

| | 카드 | 내용 | 버튼 |
|---|---|---|---|
| ① | 목표곡 · 원터치 (80%) | 곡명·가수, `남자키`·`Capo +n`·박자·BPM 칩, **오늘 구간**(그날 `songFocus`, 예: 후렴 8마디) | `악보 열기`(악보 모달) · `MR 듣기`(하단 미니 플레이어) |
| ② | 오늘의 오른손 주법 | 그날 주법 이름(`focus`)·한 줄 요약·강좌 채널/길이 | `▶ 주법 영상 보기`(미니 플레이어) · `YouTube ↗` |
| ③ | 실제 코드 곁들이기 (20% · 5분) | 그날 코드 2~3개 + **SVG 손가락 운지표** + 코드 표기(x32010 등) | (안내 한 줄) |

- 상단에 `D1~D7` 칩과 `n / 7일 완료`. 오늘 Day는 **주간 연습에서 아직 체크하지 않은 첫 Day**(전부 끝났으면 마지막 Day)이고, 칩을 누르면 그 Day로 바뀝니다(오늘 날짜에만 유효).
- 주간 연습 DAY 카드의 **`오늘의 연습으로 바로 가기`** 버튼이 그 Day를 그대로 열어 줍니다(`week-day:n`).

### 5단계 루틴 — 죽은 글자 대신 연결 버튼

| 단계 | 연결 |
|---|---|
| 1. 손 풀기 & 준비 | `메트로놈 켜기` → 목표곡 BPM·박자로 켜고 메트로놈 카드로 이동 |
| 2. 원터치 버튼 전환 / 실제 코드 | `코드 운지 보기` → ③ 카드로 스크롤 |
| 3. 오른손 리듬 (그날 주법 이름) | `▶ 주법 영상` → 미니 플레이어 |
| 4. 목표 구간 연결 (그날 구간) | `MR 듣기` → 미니 플레이어(없으면 악보) |
| 5. 오늘의 기록 | `기록 입력` → 기록 폼으로 스크롤 + 메모 자동 포커스 |

- 각 단계 분량은 Day 총 시간(25분)을 3·5·7·7·3분으로 나눠 **합이 정확히 총 시간**이 되게 계산합니다.
- `DAY n 완료 체크`는 `weekPlan.days`에 저장되고, 다음 연습 날에는 다음 Day가 자동으로 열립니다.
- 원터치/SimplifyChord 설명은 접이식(`details`)으로 내려 본문 가독성을 살렸습니다.

### 실제 코드 — 일차별 커리큘럼

`data/week-plan.json` 의 각 Day 에 `chords`·`chordsNote` 를 추가했습니다.

| Day | 주제 | 코드 | 한 줄 |
|---|---|---|---|
| 1 | 워밍업 & 8비트 | C · G | 두 코드만으로 8비트를 끝까지 |
| 2 | 코드 체인지 | C · G · Am | 바꾸는 순간 오른손이 멈추지 않게 |
| 3 | 칼립소 | C · G · F | F는 약식(xx3211)으로 먼저 |
| 4 | 16비트·고고 | G · D · Em | 키 G 진행 · 16비트로 빠르게 |
| 5 | 아르페지오 | C · Am · Em | 아르페지오에 좋은 개방현 코드 |
| 6 | 구간 연결 | Am · Dm · G | 3코드 순환으로 끊김 없이 |
| 7 | 완주 | G · C · D | 1-4-5 진행으로 전곡 완주 |

운지표는 `tools/chord_shapes.py` 의 `describe(chord, 0)` 로 만든 값(프렛·손가락·바레)을 `src/app.js` 의 `CHORD_SHAPES` 에 넣었고, 화면은 기존 `fretDiagram()` 이 그립니다.

### 바레 코드는 약식(SimplifyChord) 폼 먼저 — 주성 님 지시 반영

> "에프코드같은거는 심플리코드로 바꾸는게 낫지않나?"

- `F` → **F 약식 `xx3211`**(4현, 1번줄·2번줄 1프렛을 검지로), 풀바레 `133211` 은 보조 정보로만 둡니다.
- `Bm` → **Bm7 약식 `x20202`**, `B♭` → **B♭ 약식 `x10331`**.
- 카드에 `약식` 배지(노란 테두리)를 붙이고, 코드 카드 아래 한 줄 안내:
  **"바레가 막힐 때는 에어로밴드 SimplifyChord 약식 폼으로 먼저 연습하세요. F = xx3211"**
- 세 약식 폼은 코드 구성음(근음·3음 포함, 코드 밖 음 없음)을 음정으로 검증했습니다.

- 오늘 할 일 3카드 · Day 칩 7개 · 루틴 버튼 5개 · 코드 SVG 2개 이상

- 홈 히어로 버튼 위 최상위 요소가 `BUTTON`, 좌표 탭으로 `오늘의 연습` 진입
